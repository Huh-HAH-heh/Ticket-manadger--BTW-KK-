# Ticket Manager

**Ticket Manager** — учебная клиент-серверная система Service Desk для регистрации и обработки заявок. Проект разделяет пользовательский интерфейс, серверную бизнес-логику и хранение данных.

## Возможности

- Регистрация пользователей и вход в систему.
- Ролевое разграничение доступа: Client, Operator и Admin.
- Создание, поиск, фильтрация и обработка заявок.
- Назначение исполнителей, изменение статусов и приоритетов.
- Комментарии и история изменений заявок.
- Управление учётными записями и отчёты.

## Архитектура

```text
Консольный клиент (C#)
        │ HTTP / JSON
        ▼
ASP.NET Core Web API
        │ Entity Framework Core
        ▼
PostgreSQL
```

Клиент не обращается к базе данных напрямую. Проверка прав и обработка запросов выполняются сервером. Это позволяет менять пользовательский интерфейс отдельно от API и слоя хранения данных.

## Технологии

C# · .NET 10 · ASP.NET Core Web API · Entity Framework Core · PostgreSQL 16 · Docker Compose

## Инженерные решения

- Разделение клиента и сервера через HTTP API.
- Работа с PostgreSQL через EF Core и версионированные миграции.
- Проверка ролей и доступа на стороне API.
- Хранение паролей в виде хэшей; секреты и строки подключения вынесены из исходного кода.
- Контейнеризированный локальный запуск API и базы данных.

## Текущий интерфейс

Пользовательский интерфейс проекта — консольный клиент. API отделён от него и может обслуживать другие клиенты без переписывания серверной логики.

## Запуск и эксплуатация

Основной сценарий демонстрации использует Docker Compose для PostgreSQL и API, а консольный клиент запускается в Windows.

**[Инструкция по установке, первичной настройке, запуску, резервному копированию и устранению проблем](docs/OPERATIONS.md).**

## Структура решения

- `Ticket manadger/` — консольный клиент и HTTP-клиент API.
- `Ticket Manager API/` — ASP.NET Core API, бизнес-логика, авторизация, EF Core и миграции.
- `compose.yaml` и `Dockerfile` — локальное окружение PostgreSQL и API.
- `docs/` — эксплуатационная документация и дополнительные материалы.

## Статус

Проект находится в стадии учебной стабилизации и подготовки демонстрационного сценария. Он предназначен для изучения архитектуры клиент-серверных приложений, API, ролевого доступа и работы с реляционной базой данных; не позиционируется как готовый production Service Desk.
