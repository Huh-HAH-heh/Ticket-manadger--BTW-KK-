# Ticket Manager

Консольное приложение для управления заявками на PostgreSQL и Entity Framework Core.

## Что умеет приложение

- Просматривать заявки с ID, названием, статусом, клиентом и датой создания.
- Создавать заявки для существующего пользователя с ролью `Client`.
- Изменять название и описание заявки.
- Менять статус заявки.
- Удалять заявку после подтверждения.
- Искать по названию, описанию и имени клиента без учёта регистра.
- Фильтровать по статусу и сортировать по дате, названию или статусу.
- Просматривать статистику по статусам и клиентам.
- Проверять подключение к БД и наличие неприменённых миграций до показа меню.

## Требования

- .NET SDK 10.
- PostgreSQL.
- Доступная база данных `ticket_db`.
- Инструмент Entity Framework Core CLI версии 10 (если ещё не установлен).

## Настройка подключения

Пароль БД не хранится в исходном коде. До запуска установите переменную окружения `TICKET_DB_CONNECTION`.

PowerShell (для текущего окна терминала):

```powershell
$env:TICKET_DB_CONNECTION = "Host=localhost;Port=5433;Database=ticket_db;Username=postgres;Password=ВАШ_ПАРОЛЬ"
```

Замените порт, имя пользователя и пароль на параметры своей установки PostgreSQL. Не публикуйте строку подключения и не добавляйте её в Git.

## Подготовка базы данных

Если база ещё не создана, создайте в PostgreSQL базу `ticket_db` (или укажите своё имя в строке подключения). Затем из корня репозитория выполните:

```powershell
dotnet tool install --global dotnet-ef --version 10.0.13
dotnet ef database update --project "Ticket manadger/Ticket manadger.csproj"
```

Команда установки инструмента нужна только в том случае, если `dotnet-ef` ещё не установлен. Переменная `TICKET_DB_CONNECTION` должна быть задана в том же терминале, в котором выполняется обновление БД.

Миграция `20261023180000_AddPasswordHash` добавляет в таблицу `users` необязательное поле `passwordHash` длиной до 255 символов. Оно оставлено необязательным, чтобы существующие пользователи без пароля не блокировали обновление базы данных.

## Запуск

Из корня репозитория:

```powershell
dotnet run --project "Ticket manadger/Ticket manadger.csproj"
```

При запуске приложение проверяет подключение и сообщает, если в БД остались неприменённые миграции. Оно не изменяет схему базы автоматически.

## Примечание о паролях

В модели пользователя хранится поле для **хэша** пароля, а не исходный пароль. Этот этап добавляет поле в модель и схему БД; регистрация, вход и генерация хэша пароля пока не реализованы.
