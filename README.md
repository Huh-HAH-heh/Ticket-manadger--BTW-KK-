## Local full-stack deployment with Docker

The recommended first deployment runs **PostgreSQL and Ticket Manager API in Docker** on your PC. Use [docs/DOCKER-LOCAL-SETUP.md](docs/DOCKER-LOCAL-SETUP.md).

- Start: Start-TicketManager-Docker.cmd
- First administrator: Create-TicketManager-Admin.cmd
- Health check: http://127.0.0.1:5080/health
- Stop without deleting data: docker compose down

The console client remains a temporary Windows-side interface; the planned VK bot can replace it later. The API is bound to 127.0.0.1 only. The generated .env contains secrets and is ignored by Git. Never run docker compose down -v unless you intend to delete the Docker database volume.

## Локальная защита без Docker

Для демонстрации на одном компьютере подготовлен отдельный сценарий установки PostgreSQL как службы Windows. Он запускает API и консоль на одном ПК, поэтому для этого режима не нужны Docker, VPS, Cloudflare Tunnel или доступ к интернету после первоначальной установки.

- **Install-TicketManager-Native.ps1** — первая установка PostgreSQL 16, создание базы и пользователя приложения, EF Core migrations, сборка API и клиента.
- **Start-TicketManager-OneClick.cmd** — единая точка запуска: при первом запуске устанавливает PostgreSQL, применяет миграции и предлагает создать администратора; при следующих запусках сразу открывает приложение.
- **Start-TicketManager-Native.cmd** — прямой повторный запуск после установки.
- **Backup-TicketManager-Docker.ps1** — резервный дамп текущего Docker PostgreSQL в отдельную папку.
- **Backup-TicketManager-Native.ps1** — резервный дамп нативного PostgreSQL.
- **docs/NATIVE-WINDOWS-SETUP.md** — инструкция установки без Docker.
- **docs/GITHUB-BACKUPS.md** — сведения о контрольных точках и резервных копиях.

Исходное состояние до этих изменений сохранено в ветке **backup/defense-2026-10-24-stage5**. Новая реализация находится в ветке **feature/local-postgres-defense**; ветка **main** не изменяется.

Дамп базы данных не хранится в публичном GitHub: он может содержать заявки, контакты, историю и хэши паролей. Для локальной копии используй соответствующий скрипт резервного копирования и храни файл отдельно от репозитория.


Консольная система Service Desk на C# и .NET 10. Проект разделён на три части: консольный клиент, HTTP API и PostgreSQL.

### Консоль — `Ticket manadger/`

Это только интерфейс для пользователя. Здесь нет подключения к PostgreSQL и EF Core.

- **`Program.cs`** — запуск приложения, обработка верхнеуровневых ошибок и команды первичной настройки администратора.
- **`ConsoleMenu.cs`** — меню входа/регистрации и меню для каждой роли; ввод, подтверждения, табличный вывод, поиск и фильтры.
- **`TicketApiClient.cs`** — единая точка обмена данными с сервером через HTTP. Добавляет токен к запросам, разбирает ответы и показывает сообщения API об ошибках.
- **`Ticket manadger.csproj`** — зависимости только самого консольного клиента. Модели БД и миграции находятся не здесь.

### Сервер — `Ticket Manager API/`

Здесь находится бизнес-логика и единственная точка доступа к БД.

- **`Program.cs`** — поднимает HTTP API, проверяет настройки безопасности и валидирует токены на входящих запросах. Повторно сверяет действительность пользователя и его текущую роль с БД.
- **`Controllers/AuthController.cs`** — регистрация клиентов, вход и безопасная первичная настройка первого администратора.
- **`Controllers/RequestsController.cs`** — заявки: список, поиск, фильтры, создание, редактирование, статусы, назначение исполнителя, комментарии и история обработки. Проверяет права для каждой операции, независимо от пунктов консольного меню.
- **`Controllers/UsersController.cs`** — список пользователей, создание учётных записей администратором, изменение ролей и деактивация.
- **`Controllers/ReportsController.cs`** — сводки по статусам и клиентам, выборка просроченных заявок.
- **`AuthService.cs`** — проверка регистрации и входа, нормализация логина/email, правила к длине полей и пароля.
- **`PasswordHasher.cs`** — превращает пароль в проверяемое значение: для каждого аккаунта создаётся своя случайная добавка к паролю, после чего вычисляется PBKDF2-SHA256. Исходный пароль в БД не хранится.
- **`ApiTokenService.cs`** — формирует подписанный токен доступа с ограниченным сроком действия. Подпись API проверяется при каждом запросе; изменение роли и деактивация пользователя делают старый токен недействительным.
- **`UserRepository.cs`** — работа с учётными записями: создание, проверка уникальности логина/email, смена роли и мягкое удаление.
- **`Models.cs`** — классы данных и связь между заявками, пользователями, статусами, комментариями и историей.
- **`AppDbContext.cs`** — EF Core: таблицы, связи, индексы и начальные статусы.
- **`AppDbContextFactory.cs`** — позволяет EF Core CLI запускать миграции без запуска HTTP-сервера.
- **`Migrations/`** — версионированные изменения схемы БД.

### База данных — PostgreSQL

Основные таблицы:

| Таблица | Назначение |
|---|---|
| `users` | Логин, имя, email, роль, хэш пароля и признак деактивации |
| `requests` | Название, описание, время создания, статус, приоритет, автор и исполнитель |
| `statuses` | Справочник статусов |
| `comments` | Комментарии участников к заявке |
| `requestHistory` | Кто, когда и какое действие выполнил с заявкой |

У заявки есть автор (`clientId`) и необязательный исполнитель (`executorId`). Приоритеты: 1 — низкий, 2 — обычный, 3 — высокий, 4 — критический. При отключении учётной записи данные и история заявок сохраняются — используется `isDeleted`, а не физическое удаление пользователя.

## Как проходит один запрос

```text
Пользователь
    ↓ ввод / меню
Консольное приложение
    ↓ HTTP + токен доступа
Контроллер API
    ↓ проверка входных данных и прав
EF Core / AppDbContext
    ↓ SQL
PostgreSQL
    ↑ результат
API → консоль → таблица или сообщение
```

Консоль не обращается к базе напрямую. Поэтому права доступа применяются на сервере, а не только скрытием недоступных пунктов меню.

## Роли и доступ

**Client — клиент.** Публичная регистрация всегда выдаёт эту роль. Клиент создаёт заявки от своего имени, просматривает и ищет только свои заявки, может добавлять комментарии и редактировать новую заявку до начала обработки.

**Operator — оператор/исполнитель.** Видит заявки без исполнителя и назначенные на него, может взять свободную заявку себе, редактировать назначенную заявку, менять её статус и оставлять комментарии. Нельзя менять статус или редактировать чужую занятую заявку.

**Admin — администратор.** Просматривает все заявки, управляет ролями и учётными записями, назначает исполнителей, удаляет ошибочные заявки и просматривает аналитические отчёты.

Первого администратора создают отдельной командой с ключом первичной настройки. Публичная регистрация не позволяет назначить себе роль оператора или администратора.

## Настройка и запуск

Строка подключения и секреты остаются в переменных окружения, а не в исходном коде.

1. **В терминале API** задайте строку подключения и два секрета:

```powershell
$env:TICKET_DB_CONNECTION = "Host=localhost;Port=5433;Database=ticket_db;Username=postgres;Password=ВАШ_ПАРОЛЬ"
$env:TICKET_API_TOKEN_SECRET = "СЮДА_ДЛИННЫЙ_СЛУЧАЙНЫЙ_СЕКРЕТ_НЕ_МЕНЕЕ_32_БАЙТ"
$env:TICKET_BOOTSTRAP_KEY = "ОТДЕЛЬНЫЙ_КЛЮЧ_ПЕРВОЙ_НАСТРОЙКИ"
```

2. Примените миграции (если `dotnet-ef` уже установлен, первую команду пропустите):

```powershell
dotnet tool install --global dotnet-ef --version 10.0.13
dotnet ef database update --project "Ticket Manager API/Ticket Manager API.csproj"
```

3. В первом терминале запустите сервер:

```powershell
dotnet run --project "Ticket Manager API/Ticket Manager API.csproj"
```

4. **В отдельном терминале** укажите URL API и тот же ключ первичной настройки:

```powershell
$env:TICKET_API_URL = "http://localhost:5080"
$env:TICKET_BOOTSTRAP_KEY = "ТОТ_ЖЕ_КЛЮЧ_ПЕРВОЙ_НАСТРОЙКИ"
dotnet run --project "Ticket manadger/Ticket manadger.csproj" -- --bootstrap-admin
```

После создания администратора запустите консоль без параметров:

```powershell
dotnet run --project "Ticket manadger/Ticket manadger.csproj"
```

Для обычной работы нужен запущенный API. Секрет подписи хранится только в окружении сервера. Пароль БД и секреты нельзя отправлять в Git.
