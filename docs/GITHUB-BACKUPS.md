# Контрольные точки GitHub и резервные копии данных

## Резервная копия кода

Дополнительно после подготовки обоих сценариев защиты сделан снимок ветки:
    
    backup/defense-2026-10-24-guides-final

Эта резервная ветка содержит текущие гайды и установочные сценарии, описанные ниже.

Перед добавлением сценариев локальной установки создана ветка-снимок:

    backup/defense-2026-10-24-stage5

Она указывает на ветку feature/stage-5-console-app до изменений для локальной установки. Новая реализация находится отдельно в feature/local-postgres-defense. Ветка main не изменяется и автоматически не сливается.

Для возврата к исходной версии открой backup-ветку в GitHub или клонируй её отдельно. Не выполняй force-push в main и не перемещай backup-ветку.

## Резервные копии PostgreSQL

GitHub backup-ветка сохраняет исходный код, а не копию реальной базы. Данные PostgreSQL не следует коммитить в публичный репозиторий: дамп содержит заявки, контакты, историю и хэши паролей.

Для локальных дампов предусмотрены два сценария:

- Docker PostgreSQL: Backup-TicketManager-Docker.ps1.
- PostgreSQL, установленный без Docker: Backup-TicketManager-Native.ps1.

Оба сценария по умолчанию сохраняют файлы в %USERPROFILE%\TicketManager-Backups и создают рядом контрольную сумму SHA-256. Копируй этот каталог отдельно на флешку или в приватное хранилище. Не добавляй .dump, .env, файл состояния DPAPI или секреты в Git.
