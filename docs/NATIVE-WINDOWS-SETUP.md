# Локальный запуск Ticket Manager без Docker

Этот режим нужен для демонстрации на одном компьютере: PostgreSQL работает как обычная служба Windows, а API и консольный клиент запускаются на этом же ПК. После установки локальная демонстрация не зависит от Cloudflare Tunnel. Для первой установки потребуется интернет, чтобы загрузить PostgreSQL и NuGet-зависимости.

## Требования

- Windows 10/11 x64.
- Права администратора для установки PostgreSQL.
- Полный исходный репозиторий: оба проекта и каталог миграций API.
- winget для установки PostgreSQL 16 и при необходимости .NET 10 SDK.

## Первая установка

1. Получи полный исходный код ветки feature/local-postgres-defense, а не только ZIP опубликованного клиента.
2. Открой PowerShell в корне репозитория.
3. Выполни:

    Set-ExecutionPolicy -Scope Process Bypass -Force
    .\Install-TicketManager-Native.ps1

4. Сценарий запросит повышение прав, если нужно, установит PostgreSQL 16 без Docker, выберет свободный порт из 5432, 5434, 5435 или 5436, создаст роль ticket_app и базу ticket_db, применит EF Core migrations, соберёт API и клиент и запустит приложение.
5. При первой установке введи данные первого администратора в консоли. После проверки созданной учётной записи ключ первичной настройки будет убран из локального состояния, а API перезапустится без него.
6. Параметры сохраняются в %LOCALAPPDATA%\TicketManager-Native\state.json. Пароли защищены Windows DPAPI для текущего профиля пользователя. Не копируй этот файл в GitHub или на другой компьютер.

## Следующие запуски

Запусти Start-TicketManager-Native.cmd из корня репозитория. API работает на http://127.0.0.1:5081, а консоль использует тот же адрес. PostgreSQL не открывается наружу. Если службу PostgreSQL остановили, лаунчер попробует запустить её; если Windows откажет в доступе, запусти лаунчер от имени администратора.

## Резервные копии

- Для текущего Docker-контейнера используй Backup-TicketManager-Docker.ps1.
- Для установленного без Docker PostgreSQL используй Backup-TicketManager-Native.ps1.

По умолчанию дампы создаются в %USERPROFILE%\TicketManager-Backups; рядом хранится контрольная сумма SHA-256. Дамп содержит данные пользователей, заявки, историю и хэши паролей — держи его отдельно от исходного кода и не помещай в публичный GitHub. GitHub-ветка резервирует код, но не содержимое базы данных.

## Безопасность и ограничения

- Этот режим предназначен для локальной демонстрации, а не для публичного production-сервера.
- API привязан к 127.0.0.1:5081; база доступна только локально, внешний доступ через роутер не настраивается.
- Локальные параметры DPAPI расшифровываются только тем профилем Windows, который создал их.
- Если на компьютере уже установлена служба PostgreSQL, скрипт без собственного файла состояния остановится, чтобы не изменить существующую базу.
- Сценарий создаёт отдельную локальную базу. Он не переносит автоматически пользователей и заявки из существующей Docker-базы. Если нужны текущие данные, сначала сделай резервную копию исходной БД и отдельно спланируй восстановление.
