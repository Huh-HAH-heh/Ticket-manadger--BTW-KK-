# Эксплуатация Ticket Manager

Основной демонстрационный сценарий: **PostgreSQL и ASP.NET Core API в Docker, консольный клиент в Windows**. Для пользователя оставлена одна точка входа — `Start-TicketManager.cmd`.

## 1. Требования

- Windows 10/11 x64.
- Docker Desktop с Docker Compose v2.
- .NET 10 SDK для запуска консольного клиента.
- Интернет при первом запуске для загрузки контейнеров и сборки API.

## 2. Первый запуск

1. Склонируй репозиторий и открой его корневую папку.
2. Запусти Docker Desktop и дождись готовности движка.
3. Запусти единственный основной файл:

```cmd
Start-TicketManager.cmd
```

Он последовательно:
1. Проверяет Docker Desktop и запускает PostgreSQL с ASP.NET Core API.
2. При первом запуске создаёт локальный `.env` со случайными секретами.
3. Дожидается ответа API и проверяет подключение к базе и актуальность миграций.
4. Если одноразовый ключ первичной настройки ещё существует, открывает создание первого администратора.
5. После успешной первичной настройки запускает консольный клиент.

Проверить API отдельно можно в браузере:

```text
http://127.0.0.1:5080/health
```

Успешный ответ должен подтверждать `status=ok`, `database=connected` и `migrations=current`.

## 3. Создание первого администратора

При первом запуске `Start-TicketManager.cmd` автоматически откроет процедуру создания администратора.

1. Введи имя, логин, email и пароль в консоли.
2. Убедись, что приложение подтвердило создание учётной записи.
3. На вопрос об отключении первичной настройки введи `Y`.

После этого скрипт удалит одноразовый ключ из локального `.env` и пересоздаст контейнер API. Обычный вход останется доступен. Не подтверждай отключение ключа, если создание администратора не завершилось успешно.

Если первичная настройка была прервана, повторно запусти `Start-TicketManager.cmd`: пока ключ остаётся в `.env`, сценарий снова предложит создать первого администратора.

## 4. Повседневный запуск

После первичной настройки для запуска всей системы достаточно:

```cmd
Start-TicketManager.cmd
```

Сценарий поднимет остановленные контейнеры, проверит API и откроет консольный клиент. PostgreSQL и API продолжают работать в Docker после закрытия консоли.

## 5. Остановка и состояние

Посмотреть состояние сервисов:

```powershell
docker compose ps
```

Посмотреть журнал API:

```powershell
docker compose logs -f api
```

Посмотреть журнал PostgreSQL:

```powershell
docker compose logs -f db
```

Остановить контейнеры, сохранив базу данных:

```powershell
docker compose down
```

Повторный запуск:

```powershell
docker compose up -d
```

**Не используй `docker compose down -v` для обычной остановки.** Ключ `-v` удаляет том PostgreSQL и вместе с ним локальные данные системы.

## 6. Резервная копия

Для резервного копирования Docker-базы можно использовать:

```powershell
.\scripts\Backup-TicketManager-Docker.ps1
```

Либо самостоятельно создать SQL-дамп:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\TicketManager-Backups"
docker compose exec -T db pg_dump -U ticket_app ticket_db > "$env:USERPROFILE\TicketManager-Backups\ticket_db.sql"
```

Дамп содержит данные заявок, пользователей и хэши паролей. Храни его вне репозитория и не загружай в публичный GitHub.

## 7. Настройки и безопасность

- Параметры подключения и секреты находятся в локальном `.env`.
- Пример структуры настроек находится в `.env.example`; не используй демонстрационные значения как реальные секреты.
- API опубликован только на loopback-интерфейсе `127.0.0.1`. Это локальный демонстрационный режим, а не настройка публичного сервера.
- PostgreSQL доступен API во внутренней Docker-сети и не публикуется на хостовый порт.
- Права проверяются на стороне API; скрытие пунктов консольного меню не является единственной защитой.
- Не переноси `.env`, дампы БД или локальные секреты в Git.

## 8. Текущее ограничение миграций

В `compose.yaml` пока включён флаг `TICKET_DOCKER_ALLOW_PENDING_MODEL_CHANGES=true`. Он нужен как временный обход обнаруженного расхождения модели EF Core и snapshot при запуске учебной версии. Это не замена корректной миграции схемы. Перед использованием проекта вне учебной демонстрации нужно синхронизировать миграции и snapshot, затем удалить этот флаг.

## 9. Типовые проблемы

| Симптом | Что проверить |
|---|---|
| Docker не найден | Установить Docker Desktop и проверить команду `docker --version` |
| Docker Engine недоступен | Запустить Docker Desktop и дождаться готовности |
| Ошибка сборки API | Выполнить `docker compose logs --tail 100 api` |
| API не проходит health check | Проверить журналы API и PostgreSQL командами выше |
| Порт 5080 занят | Изменить `TICKET_API_PORT` в локальном `.env` и повторить запуск |
| Консоль не запускается | Проверить наличие .NET 10 SDK |
| Не удаётся создать администратора | Проверить наличие непустого `TICKET_BOOTSTRAP_KEY` в `.env` и повторить запуск |

Резервная копия старой Native-установки, если она всё ещё используется, находится в `legacy/native/Backup-TicketManager-Native.ps1`.

## 10. Альтернативный режим

В репозитории исторически сохранён сценарий установки PostgreSQL как службы Windows без Docker. Он не нужен для стандартной демонстрации и не является основным способом эксплуатации проекта. Для портфолио используй Docker-сценарий из этой инструкции.
