# Ticket Manager: гайд по двум вариантам защиты

Есть два разных способа запустить проект. Выбирай по тому, где будет компьютер с базой и можно ли устанавливать программы в колледже.

## Вариант A — клиент в колледже, база и API дома

**Подходит**, если дома есть ПК, который можно оставить включённым, а на компьютере колледжа можно запустить EXE с флешки.

- PostgreSQL работает в Docker на домашнем ПК.
- API работает на домашнем ПК по localhost.
- Cloudflare Quick Tunnel предоставляет временный HTTPS-адрес API.
- Консольный клиент упакован в автономный ZIP для Windows x64.
- Компьютер колледжа не должен устанавливать PostgreSQL, Docker или .NET SDK.

Инструкция: [DEFENSE-SCENARIO-A-DOCKER-CLOUDFLARE.md](DEFENSE-SCENARIO-A-DOCKER-CLOUDFLARE.md).

**Какой архив использовать:** TicketManager-College.zip — клиентский архив. Его создаёт сценарий на домашнем ПК. Он не включает базу или API. Перед защитой проверь URL /health. Если Quick Tunnel перезапустили, возьми новый URL и пересобери ZIP.

**Минус:** домашний компьютер, API, Docker и туннель должны оставаться запущенными. При падении домашнего интернета клиент из колледжа не подключится.

## Вариант B — всё локально на одном компьютере, без Docker

**Подходит**, если ты можешь запускать установку на том же компьютере, где состоится защита, и у тебя есть права администратора Windows.

- PostgreSQL устанавливается как системная служба Windows.
- API и консоль работают на том же ПК.
- Внешний доступ, VPN и Cloudflare не нужны.
- После первой установки локальная демонстрация не требует интернета.

Инструкция: [DEFENSE-SCENARIO-B-LOCAL-WINDOWS.md](DEFENSE-SCENARIO-B-LOCAL-WINDOWS.md).

**Какой архив использовать:** полный ZIP исходного проекта из ветки feature/local-postgres-defense:
https://github.com/Huh-HAH-heh/Ticket-manadger--BTW-KK-/archive/refs/heads/feature/local-postgres-defense.zip

После распаковки запускается Start-TicketManager-OneClick.cmd. Не используй для этого варианта TicketManager-College.zip — в нём находится только консольный клиент.

**Минус:** первая установка требует прав администратора, интернета и места для PostgreSQL/.NET-зависимостей. На компьютере колледжа сначала уточни, разрешена ли установка программ.

## Сравнение

| Вопрос | Вариант A | Вариант B |
|---|---|---|
| Где база | Docker на домашнем ПК | PostgreSQL-служба на компьютере защиты |
| Где API | Дома | На том же компьютере |
| Где клиент | Колледж | Тот же компьютер |
| Нужен интернет во время защиты | Да, между колледжем и домом | Нет для локальной работы после установки |
| Нужен Docker | На домашнем ПК | Нет |
| Нужны права администратора | Обычно нет на ПК колледжа | Да, при первой установке |
| Перенос существующих заявок | База остаётся дома | Нужен отдельный backup/restore, автоматически не переносится |

## Подготовка накануне

1. Выбери один вариант и следуй только его инструкции.
2. Создай администратора и демонстрационные учётные записи заранее.
3. Создай несколько демонстрационных заявок с разными приоритетами и статусами.
4. Проверь полный сценарий: вход, список заявок, создание, смена статуса, комментарий, история и отчёт.
5. Создай дамп БД локальным скриптом и скопируй его отдельно на флешку.
6. Не загружай дамп в публичный GitHub: он может содержать личные данные и хэши паролей.
