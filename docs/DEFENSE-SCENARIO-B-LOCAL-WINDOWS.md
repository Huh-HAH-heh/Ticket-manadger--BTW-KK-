# Сценарий B: PostgreSQL, API и клиент на одном Windows-ПК без Docker

## Когда выбирать

Выбирай этот вариант, если во время защиты будешь работать за одним компьютером и хочешь, чтобы система работала даже без интернета после установки. PostgreSQL устанавливается как служба Windows; API и клиент запускаются локально. Cloudflare, VPN и открытие портов роутера не нужны.

## Ключевое условие

Для первой установки нужны права администратора Windows и интернет, чтобы установить PostgreSQL и восстановить NuGet-пакеты. Если это компьютер колледжа и политика запрещает установку программ или запуск от администратора, используй сценарий A с переносимым клиентом, либо заранее согласуй локальную установку с преподавателем/администратором.

## Как устроено

    Ticket Manager Console
             │ HTTP localhost:5081
             ▼
    Ticket Manager API
             │ localhost:5432/5434/...
             ▼
    PostgreSQL 16 как служба Windows

API слушает только 127.0.0.1. PostgreSQL не выставляется в интернет. При обычной демонстрации приложение полностью работает на одном компьютере.

## Какой архив скачать

Нужен **полный исходный код**, в котором есть каталоги Ticket Manager API, Ticket manadger и миграции. Клиентский TicketManager-College.zip здесь не подходит: в нём только консольное приложение и нет сервера или установщика базы.

Загрузи полный ZIP ветки feature/local-postgres-defense:

https://github.com/Huh-HAH-heh/Ticket-manadger--BTW-KK-/archive/refs/heads/feature/local-postgres-defense.zip

Распакуй его в обычную папку, например Documents\TicketManager. Не запускай установщик из архиватора, сначала полностью распакуй каталог.

## Первая установка — один запускатель

1. Дважды щёлкни Start-TicketManager-OneClick.cmd в корне распакованного проекта.
2. Если Windows запросит подтверждение UAC, подтверди установку, если на этом компьютере у тебя есть соответствующие права.
3. Установщик проверит .NET 10 SDK, установит PostgreSQL 16 без Docker, выберет свободный порт среди 5432, 5434, 5435, 5436, создаст служебную роль ticket_app и базу ticket_db.
4. Скрипт восстановит NuGet-зависимости, применит EF Core migrations, соберёт API и клиент.
5. Если активного администратора в новой базе ещё нет, консоль попросит создать первого администратора. Введи имя, логин, email и пароль непосредственно в консоли.
6. После подтверждения успешного создания учётной записи ключ первичной настройки отключается.
7. Консольное меню откроется на этом же компьютере.

Если установщик сообщает, что уже есть служба PostgreSQL, но локальный файл состояния отсутствует, он остановится, чтобы не менять существующую базу. Не удаляй службу и каталоги PostgreSQL; сначала выясни, что уже установлено.

## Последующие запуски

Дважды щёлкни Start-TicketManager-OneClick.cmd снова. После успешной первой установки он распознает состояние и запустит локальный API с консольным приложением.

Если нужно запустить именно существующую установку без проверки первого запуска, можно использовать Start-TicketManager-Native.cmd.

Локальное состояние хранится в:

    %LOCALAPPDATA%\TicketManager-Native\state.json

Пароли и секреты защищены Windows DPAPI для текущего профиля пользователя. Не копируй файл состояния в GitHub и не переноси его на другой компьютер.

## Резервная копия базы

Запусти PowerShell из корня полного проекта:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Backup-TicketManager-Native.ps1

По умолчанию дамп сохраняется в %USERPROFILE%\TicketManager-Backups, рядом создаётся SHA-256. Скопируй дамп отдельно на флешку или в приватное хранилище. Не помещай его в публичный GitHub.

Сценарий устанавливает **отдельную пустую базу**. Он не переносит автоматически данные из контейнера ticket-postgres. Если важно сохранить заявки из Docker-варианта, сначала создай дамп через Backup-TicketManager-Docker.ps1, а восстановление в новую базу выполняй только по отдельной инструкции; не перезаписывай существующую базу наугад.

## Проверка готовности

В новом PowerShell выполни:

    Invoke-RestMethod "http://127.0.0.1:5081/health"

Ожидай status=ok, database=connected, migrations=current. Затем войди под созданным администратором, создай тестовую заявку, поменяй статус и добавь комментарий.

## Ограничения

- После первоначальной установки демонстрация может идти без интернета; интернет всё ещё понадобится для действий, требующих внешних сетевых ресурсов.
- Компьютер нельзя выключать во время демонстрации.
- Скрипт не мигрирует данные из Docker автоматически.
- Не используй эту настройку как публичный production-сервер.
- Если компьютер принадлежит колледжу, не пытайся обходить административные ограничения: заранее попроси разрешение на установку.
